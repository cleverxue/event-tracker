## 四、建设过程中发现并修复的数据质量问题

按时间序，全部有回归测试固化：

1. **巨潮 fulltextSearch 日期格式**：须 `YYYY-MM-DD`，传 `YYYYMMDD` 返 500 → 已修并加 5xx 重试
2. **分类器缺家族门禁**："增持计划实施完毕"被回购族"实施完毕"截胡 → 家族关键词门禁
3. **标题花样不连续**："回购A股股份方案""解除《股份转让协议》""方案实施进展" → 子串升级正则窗口
4. **价格正则不认千分位**：茅台 1,887.63 元/股 整类漏抽 → `_NUM` 加千分位容忍
5. **调价公式减法误判区间**："27.10元/股-0.1元/股=27元/股" → range 分隔符去掉连字符（全表 5 例清零）
6. **股权激励语境污染**：豫园股份把员工限售股回购价 5.37 当作本次回购价 → 匹配回看前文 40 字，含"限制性股票/激励计划"则跳过（修复后正确抽到 8.60）
7. **港股 5 位代码混入**：cninfo 全文检索返回港股公告（A+H 公司的港股通道行是其 A 股行的重复）→ 6 位 A 股代码规则剔除（全表 139 行）
8. **限制性股票定向回购混入回购族**：北交所 920 系股权激励行为，非二级市场回购 → 标题含"限制性股票"的 initial 不入库（12 行）
9. **抽检脚本 join 静默失配**：审计 CSV 未指定 `dtype=str`，disclosure_id 被 pandas 转 int64，导致关键词交叉验证被跳过、误标率假性为 0 → 已修（修复后真实测出 2% 并定位到问题 5）

## 五、与规格的差异标注（规格未覆盖细节的最简方案选择）

1. **extract_events.py 的复用方式**：该脚本输出为事件风险向 schema（direction/severity），
   不含 watchlist 所需价格字段。本系统在其缓存的原文之上自建三事件族抽取层
   （复用其金额千分位正则的同源思路），拉取层仍完整使用其 `fetch_announcements.py`。
   规格"输出 schema 必须与数据模型一致"在本系统侧满足。
2. **关键词映射最小扩写**：规格 5.2 状态机关键词面向真实标题扩写为
   （方案/预案→planned、实施结果→completed、标题含"进展"→in_progress、
   "过户"→completed、"解除…协议"→terminated 等），已在代码注释与本文档标注。
3. **watchlist 行粒度**：一行 = 一份初始公告（disclosure_id）。同一项目既有预案又有
   报告书时形成两行（如艾力斯、豫园股份），状态机在 M2 对同族 watching 行统一推进。
4. **symbol 格式**：纯 6 位代码（腾讯行情、TDX 均兼容）；parquet 中日期字段以
   `datetime64[ns]`（零点）存储，语义为 date。
5. **Python 版本**：开发用 managed 3.13 venv，代码按 3.11 兼容编写（无 3.12+ 语法），
   Docker 镜像为 python:3.11-slim，运行时版本满足规格。
6. **新增依赖 pdfplumber**：规格点名使用的 skill 脚本本身依赖它（其 requirements.txt
   亦列明），非本系统额外引入。

## 六、已知边界（移交 M2）

1. "提议回购"提示性公告（实控人/董事长提议，早于董事会预案）不入 watchlist——
   规格状态机从"回购报告书/预案"起算；此类公告在审计表中标记 unclassified。
2. 以协议转让方式减持的公告按关键词驱动进入协议转让族（规格未要求排除减持）。
3. 调价类公告（"调整回购价格"）作为独立 initial 行入库，价格多为 none（公式文本），
   交 M3 的 Ollama 回填；更优做法是更新原事件行价格，留待 M2 状态机设计时权衡。
4. 交易日历截至最后已知交易日，对发布日为最新交易日的公告，tracking_start 走
   工作日兜底（周六日顺延周一），节假日内可能偏差一天；生产环境建议每周刷新日历。
5. 多项目个股（同一公司两个并行回购方案）的进展公告归属存在歧义，M2 状态机按
   "同族 watching 行统一推进、均价取最新进展公告"处理，已在 M2 方案中标注。

## 七、M1 结论

**两项硬指标均达到：price_type 误标率 0.0%（<10%）、tracking_start 违规 0（100% 晚于公告日）。**
数据层可以进入 M2（进展管线）。
