# Event Taxonomy — 事件分类、字段与规则

事件分**两层**，定位由与 Pandadata 结构化能力的关系决定（详见 SKILL.md「与 event-risk-alert 的分工」）：

- **Tier A · 主力层（primary）** —— Pandadata **无结构化接口**的事件，靠公告原文才能拿到。
  这是本技能的核心价值，`event-risk-alert` 想报警也无米下锅。
- **Tier B · 补充层（supplement）** —— Pandadata **已有结构化接口**的事件（`event-risk-alert`
  已直接消费）。本技能**不与其争这块结构化数据**，只抽取 Pandadata feed **丢失的文本细节**
  （平仓线、减持原因、预告措辞差异等）作为交叉校验，不作为主力。

抽取时**规则优先、只按标题分类**（见文末「分类精度原则」），LLM 仅补规则未覆盖的空字段。
约定：`direction ∈ {利好, 利空, 中性}`，`severity ∈ {高, 中, 低}`；规则未覆盖 → `中性 / 低` 且降 `confidence`。

# Tier A · 主力层（Pandadata 盲区）

## A1. 监管问询 / 关注函（event_type = `regulatory_inquiry`，tier=primary）

- 标题关键词：`问询函` / `关注函` / `监管函` / `警示函` / `立案` / `处罚`
- 子类型：`问询函` `关注函` `立案调查` `行政处罚`
- 必抽字段：`subject`（发函方：交易所/证监会）、`topic`（问询主题摘要）
- 规则：一律 `利空`
  - severity：`立案调查`/`行政处罚` → `高`；`监管函`/`警示函`/`问询函`/`关注函` → `中`
- 为何是白空间：Pandadata **无问询/监管函接口**，只能从公告文本获取。

## A2. 重大诉讼 / 仲裁 / 对外担保（event_type = `litigation_guarantee`，tier=primary）

- 标题关键词：`诉讼` / `仲裁` / `对外担保` / `涉案` / `被告` / `原告`
- 子类型：`诉讼` `仲裁` `对外担保`
- 必抽字段：`magnitude`（涉案/担保金额）、`role`（原告/被告/担保方）、`counterparty`
- 规则：
  - 被告 / 新增大额对外担保 → `利空`；作为原告胜诉/追回 → `中性`~`利好`
  - severity：涉案或担保金额 ≥ 1亿元 → `高`；否则 `中`（有净资产口径时按占比 10%/5% 细分）
- 为何是白空间：Pandadata **无诉讼/担保结构化接口**。

## A3. 重组 / 收购 / 重大合同（event_type = `restructuring`，tier=primary）

- 标题关键词：`重大资产重组` / `发行股份购买资产` / `收购` / `重大合同` / `中标`
- 子类型：`重组预案` `重组进展` `收购` `重大合同`
- 必抽字段：`magnitude`（交易/合同金额）、`counterparty`、`stage`（预案/进展/完成/终止）
- 规则：
  - 预案 / 中标 / 收购推进 → `利好`；终止 / 失败 → `利空`
  - severity：借壳 或 金额 ≥ 10亿元 → `高`；否则 `中`
- 为何是白空间：Pandadata 无重组预案/合同的结构化文本；细节只在公告里。
- ⚠️ 注意"关联交易公告"等笼统标题里可能藏实质重组——**规则不臆测，交由 `--llm` 兜底**。

## A4. 治理决议（event_type = `governance`，tier=primary）

- 标题关键词：`股东大会决议` / `董事会决议` / `换届` / `辞职` / `选举` /
  `利润分配` / `权益分派` / `回购` / `高送转` / `分红`
- 子类型：`股份回购` `利润分配` `高管变动` `董事会决议` `股东大会决议`
- 必抽字段：`resolution`（议案摘要），高管变动/否决议案单列
- 规则：
  - `回购`（标题含）→ `股份回购` / `利好` / `中`
  - `利润分配`/`权益分派`/`分红`/`高送转` → `利润分配` / `利好` / `中`
  - 核心高管非正常辞职 或 议案被否 → `利空` / `中`
  - 常规 `董事会决议`/`股东大会决议` → `中性` / `低`
  - **周期性会议不合并**：每次决议是独立事件，即使标题相同也按 `disclosure_id` 保持独立。
- 为何是白空间：Pandadata 无治理决议内容接口；回购/分红意向的文本先于结构化数据披露。

## A5. 停牌 / 复牌 / 控制权变更（event_type = `suspension`，tier=primary）

- 标题关键词：`停牌` / `复牌` / `控制权变更` / `实际控制人变更` / `控股股东变更` /
  `易主` / `要约收购` / `入主`
- 子类型：`控制权变更` `停牌` `复牌`
- 必抽字段：`counterparty`（受让方/交易对手）、`reason`（停牌事由摘要）
- 规则：
  - 标题含 `控制权变更`/`易主`/`要约收购`/`实际控制人变更`/`控股股东变更`/`入主`
    → `控制权变更` / **`中性`** / `高`（**方向按实测定为中性**，见下方 ⚠️）
  - 标题含 `复牌`（且非停牌）→ `复牌` / `中性` / `低`
  - 其余一般重大事项停牌 → `停牌` / `中性` / `中`（方向待定，复牌后才兑现，不臆测）
- 为何是白空间：Pandadata 无停牌/控制权变更结构化接口；停牌事由与交易对手只在公告文本。
- ⚠️ 优先级高于 `restructuring`（收购）与 `holding_change`（协议转让）：控制权变更/要约收购
  语义更高一级，须优先归此类，避免被"收购/协议转让"抢分类。
- ⚠️ **控制权变更方向：经验直觉是"易主=利好"，但实测（2022–2024, n=605）推翻了它——
  复牌后中位超额 −1.3%/T+20、跑赢占比仅 44%，均值仅靠 ~8% 的借壳大牛（最大 +138%）
  拉成微正。这是正偏度"彩票"分布：单只大概率跑输，edge 在右尾。故方向定为 `中性`、
  severity `高`（高波动/重大）。想吃 tail alpha 需分散成篮子，见 [[l3-evidence]]。**

# Tier B · 补充层（Pandadata 已结构化，仅取文本细节）

> 定位：这 3 类 `event-risk-alert` 已通过 Pandadata 接口覆盖（`get_stock_pledge` /
> `get_stock_shareholder_change` / `get_fina_forecast`）。本技能**不重复产出结构化字段**，
> 只在 `detail` 字段抽取 Pandadata feed 丢失的**文本级细节**，供交叉校验；
> 若下游已用 Pandadata，Tier B 可整体忽略。

## B1. 股东增减持（event_type = `holding_change`，tier=supplement）

- 标题关键词：`增持` / `减持` / `协议转让` / `被动稀释`
- 子类型：`增持意向` `增持结果` `减持意向` `减持结果`（`拟` → 意向，否则结果）
- 结构化字段（与 Pandadata 重叠，仅作校验）：`subject`、`magnitude`（股数/比例）
- **文本细节 `detail`（Pandadata 无、本层重点）**：减持原因（个人资金需求/偿债）、价格区间、实施节奏
- 规则：增持 → `利好`；减持 → `利空`
  - severity：控股股东/实控人 或 比例 ≥ 1% → `高`；≥ 0.5% → `中`；否则 `低`

## B2. 股权质押（event_type = `pledge`，tier=supplement）

- 标题关键词：`股权质押` / `质押` / `解除质押` / `补充质押` / `平仓`
- 子类型：`质押` `解质押` `补充质押` `平仓风险`
- 结构化字段（与 Pandadata 重叠）：`subject`、`magnitude`（质押比例）、`pledgee`
- **文本细节 `detail`（Pandadata 无、本层重点）**：平仓线/警戒线、质押用途、是否触及预警
- 规则：新增/补充质押 → `利空`；解除 → `利好`；平仓/预警 → `利空` / `高`
  - severity：累计质押占总股本 ≥ 5% → `高`；≥ 2% → `中`；否则 `低`

## B3. 业绩预告与修正（event_type = `earnings_preview`，tier=supplement）

- 标题关键词：`业绩预告` / `预增` / `预减` / `扭亏` / `首亏` / `业绩预告修正`
- 子类型：`预增` `预减` `扭亏` `首亏` `预告修正`
- 结构化字段（与 Pandadata 重叠）：`magnitude`（净利润同比区间）、`period`
- **文本细节 `detail`（Pandadata 无、本层重点）**：修正前后措辞差异、原因说明
- 规则：预增/扭亏/上修 → `利好`；预减/首亏/下修 → `利空`
  - 方向判定：`增长/增加/上升` vs `下降/减少/亏损`（不止字面"预增/预减"）
  - severity：|同比| ≥ 50% 或 扭亏/首亏 → `高`；≥ 20% → `中`；否则 `低`

## 合并与去重规则

- 键：`(symbol, event_type, event_subtype, subject)`。同键的多次披露（预案→进展→结果）
  合并为一条，`timeline` 记 `disclosure_id` 链，`stage` 标"结果"，`ann_date` 取最新。
- **周期性决议例外**：`董事会决议`/`股东大会决议` 每次独立，按 `disclosure_id` 保持不合并。
- 跨源（cninfo/交易所）同 `disclosure_id` 或标题高度相似 → 去重，保留信息最全者。

## 分类精度原则（实测校准）

- **只按标题分类**：A 股公告标题高度标准化、精确；PDF 正文噪声大（"关联交易公告"正文会提"收购"，
  "半年报"会提"分红/减持"）。按正文分类会大量误报，故 `classify()` 只匹配**标题**，正文只抽字段。
- **精度优先于召回**：作为数据供给层，宁漏勿误——笼统标题的实质事件交由可选 `--llm` 兜底。
- **subject 只取具体主体**：控股股东/实控人/第一大股东/高管/交易所/证监会；剔除"股东/董事/监事"泛词。

## confidence 打分

- 规则命中且必抽字段齐全 → `0.9`
- 规则命中但部分字段靠 LLM 补 → `0.7`
- 仅 LLM 分类、规则未命中 → `0.5`（并在 `summary` 标注"待人工复核"）
